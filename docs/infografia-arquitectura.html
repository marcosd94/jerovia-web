Cómo funciona el sitio y su base de datos

Una sola aplicación muestra el sitio, sirve el panel de administración y habla con la base. El navegador nunca toca la base directamente.

1. El mapa general

Se define cada dato una vez; de esa definición salen la tabla, el panel de carga y la API. El sitio público solo lee y dibuja.

Lo que ve el público Lo que usa el equipo El núcleo: datos y permisos Donde se guarda todo

Los permisos viven en el núcleo, no en la pantalla: aunque alguien viera un botón, el servidor igual decide si puede hacer la acción.

2. La tecnología de base

Un solo proyecto, un solo lenguaje (TypeScript). Next.js arma el sitio y Payload CMS aporta el panel, la API y los permisos, todo dentro de la misma aplicación.

Node.js 20.9 o superior. Se elige la base según DATABASE_URL: el código no cambia.

3. ¿Qué tipo de API consume el frontend?

El sitio público no usa una API por HTTP: lee los datos con llamadas a funciones dentro del mismo programa. Solo el panel usa REST.

Sitio público Panel del equipo Núcleo

GraphQL está desactivado: menos superficie de ataque. Si una app móvil o un sistema externo necesita datos, la API REST ya existe y respeta los mismos permisos.

4. Qué pasa cuando alguien hace clic

Dos recorridos distintos, según el clic ocurra en el sitio público o en el panel.

En el sitio público no hace falta escribir una API: la función submitLead es una Server Action y Next.js crea el canal solo. El servidor vuelve a validar todo, porque lo que llega de afuera no es confiable.

5. Crear un ABM nuevo (ejemplo: Ciudades)

Un archivo de definición produce cuatro cosas. Después, solo falta leer los datos y dibujarlos.

  1. 1. DefinirCrear src/collections/Cities.ts
  2. 2. RegistrarSumarla en payload.config.ts
  3. 3. Generarnpm run generate:types y reiniciar
  4. 4. LeergetCities() en data.ts
  5. 5. MostrarPágina o componente que la usa

En producción las tablas no se crean solas: cada cambio de modelo va con una migración versionada y copia de seguridad previa.

6. Cuentas de clientes y compra sin cuenta

Las cuentas ya están implementadas (registro, ingreso, datos, direcciones, pedidos). El carrito que las usa llega en la próxima fase: las dos formas de comprar van a existir siempre.

El pedido siempre guarda una copia de los datos del cliente. Un pedido de invitado se vincula a la cuenta recién cuando el correo está verificado. Los datos de tarjeta nunca pasan por nuestro servidor.
